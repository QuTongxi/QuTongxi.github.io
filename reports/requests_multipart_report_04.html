Multipart POST does not work correctly when Content-Type is defined on the session

Bug Report

Multipart uploads may not be prepared correctly when a requests.Session already has a Content-Type header defined. The session-level header can override the generated multipart boundary.

Reproduction Code

import requests

session = requests.Session()
session.headers.update({"Content-Type": "application/json"})
files = {"file": ("example.txt", b"hello world", "text/plain")}
data = {"name": "example"}
response = session.post("https://example.com/upload", data=data, files=files)

Expected Behavior

When files are provided, Requests should prepare the request as multipart form data. The final Content-Type header should include the generated multipart boundary, even if the session previously defined a different Content-Type.

Requirements

  • Reproduce the multipart POST behavior with session-level Content-Type
  • Inspect request preparation and session header merging logic
  • Ensure multipart boundary is preserved in final headers
  • Add tests for multipart with pre-existing session Content-Type
  • Don't break existing JSON/session behavior
